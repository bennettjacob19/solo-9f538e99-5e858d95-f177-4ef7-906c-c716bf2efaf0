# TCP 延迟代理 + 旁路比对（慢链路复现与升级验证工具）

带网页的 TCP 延迟代理：可配置目标地址与上下行延迟，网页上直接上传文件试传，
实时显示每条连接的回执、双向字节数、缓冲峰值与回执预览。用于在本地复现慢链路下
“上传结束却收不到回执”的问题。

在此基础上新增**旁路比对**：同一次上传，主链路照常连主接收端并把上行复制给候选
（升级版）接收端，网页按连接并排显示两端下行流的字节数、SHA-256、进度与失败原因，
用于在设备接入升级前确认新旧服务响应是否一致。

## 快速开始（Docker Compose）

```bash
docker compose up --build
```

* 网页 / API：http://localhost:8000
* TCP 延迟代理监听：`localhost:7000`（可直接对接设备或客户端）
* 主接收端：容器网络内 `receiver:9000`（先发欢迎行，读到 EOF 后回
  `RECEIPT bytes=<n> sha256=<hex>`）
* 候选接收端：`receiver-candidate:9000`，故障控制接口 `receiver-candidate:9100`
  （代理通过 `CANDIDATE_CONTROL_URL` 调用，网页上可开关）

网页上可修改监听地址/端口、主目标地址、上下行延迟、是否启用旁路及候选地址，
保存后对**之后建立的连接**生效；已建立的连接沿用建立时的配置（含候选地址）。

## 旁路比对语义

1. **连接级快照**：候选地址与开关在 accept 时随配置快照，整条连接沿用。
2. **客户端只收主端**：主链路的上行、下行延迟与“待发字节冲刷完再转发 EOF”的
   半关闭语义完全不变；上行每读到一块就复制给旁路。
3. **旁路独立**：独立 TCP 连接、独立任务、独立的 64 KiB 待发应用缓冲。候选
   慢读、连接失败、写入报错、EOF 冲刷超时都只会中止旁路并标“不完整”，不会
   对主链路施加背压或抛异常。
4. **有界复制**：旁路待发缓冲最多 64 KiB；将超限时立即中止并标记“不完整”
   （已复制的字节数保留在统计里）。
5. **顺序与半关闭**：未中止时，旁路按复制顺序把上行全部发出后再 `write_eof`
   转发半关闭，然后读到候选 EOF。
6. **5 秒宽限**：主连接结束后最多再等 5 秒；届时候选仍未结束则清理旁路并标
   “不完整”。
7. **判定**：两端下行流都在读取时**增量**计算字节数与 SHA-256（不保存全量
   响应，TCP 分块方式不影响结果）。只有两端都完整、主/候选均无异常，且字节数
   与 SHA-256 都相同才判“一致”；任一端异常（连接失败、写错误、宽限超时、
   流未读完）都判“不完整”，绝不判“一致”。两端完整但摘要不同判“不同”。

状态：`disabled` 未启用 / `pending` 比对中 / `match` 一致 / `mismatch` 不同 /
`incomplete` 不完整（附原因）。

## 网页演示

* “候选端故障模拟”卡片可切换候选接收端的三种故障：
  * **回执改字**：SHA-256 改一个字符、字节数不变 -> 比对显示“不同”；
  * **慢读**：每读取一块前休眠指定毫秒 -> 旁路在 5 秒宽限后被判“不完整”，
    主链路延迟与回执不受影响；
  * **收到首块后断连** -> 旁路“不完整”，主链路照常完成。
* 上传试传返回**连接号**；页面立即显示主链路结果并开始轮询该连接的比对进度，
  不等待旁路结束。
* “活动连接”/“历史连接”表格每行列出主端下行与候选下行的字节数、SHA-256、
  完整性，旁路上行“已发/已复制”进度条，以及比对状态与失败原因。

## 关键语义（实现于 `proxy/app/engine.py`）

* **延迟起算**：每个数据块的投递时刻 = 代理读到它的时刻 + 延迟；队列按
  FIFO 投递，连续数据流水通过延迟线，不按读取块数累加等待。
* **64 KiB 应用缓冲**：每方向“已读未写”字节数上限 64 KiB，满则暂停该向
  读取（反向与别的连接不受影响）。
* **半关闭**：收到单向 EOF 后，先把该向待发字节全部写出，再 `write_eof`
  转发半关闭；反向继续传输直到结束。主端下行流的 SHA-256 在 EOF 真正转发
  之后才定稿。
* **断连释放**：正常结束或对端 RST 都会取消泵任务、清空队列、关闭两侧
  连接（以及旁路），并把连接移入历史表。
* **配置快照**：每条连接在 accept 时快照配置，整条连接沿用。

### 已知边界

* 当上行/下行延迟设为 0 且候选端写入速度跟不上主链路突发读取时，旁路可能在
  建立窗口内触及 64 KiB 待发上限而被判“不完整”。这是有界复制的规格行为
  （内存上限优先）；默认演示配置（各 300 ms）与常见慢链路不会触发。
* 旁路不重放主端的下行；候选端必须像真实接收端一样自己产生响应。

## 本地开发（不用 Docker）

```bash
pip install -r proxy/requirements.txt
PORT=19000 python3 receiver/server.py &
PORT=19100 CONTROL_PORT=19101 python3 candidate/server.py &
cd proxy && LISTEN_PORT=17000 TARGET_HOST=127.0.0.1 TARGET_PORT=19000 \
  UP_DELAY_MS=300 DOWN_DELAY_MS=300 \
  COMPARE_ENABLED=1 CANDIDATE_HOST=127.0.0.1 CANDIDATE_PORT=19100 \
  CANDIDATE_CONTROL_URL=http://127.0.0.1:19101 \
  uvicorn app.main:app --host 127.0.0.1 --port 18000
```

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/config` | 当前配置与监听状态（含旁路开关/候选地址） |
| POST | `/api/config` | 更新配置（仅影响新连接） |
| GET | `/api/connections` | 活动+历史连接：双向字节数、缓冲、回执尾部、比对详情 |
| GET | `/api/connections/{id}` | 单条连接详情（含比对状态，供试传后轮询） |
| POST | `/api/test-upload` | multipart 上传文件，经代理试传，返回回执与**连接号**；不等旁路结束 |
| GET | `/api/candidate` | 读取候选接收端故障配置 |
| POST | `/api/candidate` | 设置候选端 `mutate` / `slow_read` / `slow_read_ms` / `disconnect` |
| POST | `/api/history/clear` | 清空历史连接 |

## 自测

先按上面“本地开发”起好主接收端、候选接收端与代理（端口见脚本头注释：

```bash
python3 tests/selftest.py          # 延迟、缓冲、半关闭、配置快照、并发、RST
python3 tests/selftest_compare.py  # 旁路：一致/改字/慢读/断连/不可达/溢出/快照/关闭
```

`selftest_compare.py` 覆盖：

* 一致的字节数、SHA-256 与候选上行字节数、64 KiB 缓冲峰值；
* 候选改字 -> `mismatch`，主端回执仍正确；
* 候选慢读超 5 秒宽限 -> `incomplete`，主链路延迟与回执不变；
* 候选断连 / 不可达 -> `incomplete`，绝不判一致；
* 旁路待发缓冲溢出 -> `incomplete`，主链路正常；
* 连接建立时的候选地址快照（中途改配置不影响该连接）；
* 关闭比对后不发起旁路。

## 目录结构

```
docker-compose.yml      # proxy + 主接收端 + 候选接收端 一键启动
proxy/
  Dockerfile
  requirements.txt
  app/
    main.py             # FastAPI：配置/统计/试传/候选控制/网页
    engine.py           # 延迟代理引擎 + 旁路比对（asyncio，无第三方依赖）
    static/index.html   # 网页
receiver/
  Dockerfile
  server.py             # 主接收端：欢迎行 + EOF 后回执(字节数+SHA-256)
candidate/
  Dockerfile
  server.py             # 候选接收端：同样协议 + 改字/慢读/断连故障模拟与控制接口
tests/
  selftest.py           # 主链路端到端自测
  selftest_compare.py   # 旁路比对端到端自测
```
